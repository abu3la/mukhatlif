# Moving mukhtalif.net to the new site

Runbook for replacing the WordPress site at `https://mukhtalif.net` with the new
web app that runs today at `https://staging.mukhtalif.net`. Requested by
Abdulrahman Othman on 9 November 2026: keep sponsor redirect pages such as
`/vennre/`, keep the search value of article links, connect GA4 and Search
Console. Nothing in this document is done automatically; the cutover itself is
an owner decision and a Hostinger change (see AGENTS.md).

## 1. What the old site has (audit of 14 November 2026)

Every URL in the WordPress sitemaps (8 sitemaps, 124 URLs) was replayed against
the new site, plus the 19 non-article rows of `url_redirects` in production.

| Old URLs                                                                                   | Count | Before this change                       | After this change and the redirect script             |
| ------------------------------------------------------------------------------------------ | ----- | ---------------------------------------- | ----------------------------------------------------- |
| Articles (`/12fdk/`, Arabic slugs)                                                         | 56    | Reached the article after 3 redirects    | 1 redirect (301)                                      |
| Programme pages (`/petroly/` …)                                                            | 15    | Not found                                | 1 redirect to `/shows/<slug>`                         |
| Sponsor pages (`/vennre/` …)                                                               | 7     | Not found                                | 1 redirect (302) to the destination the old page used |

Existing WordPress Redirection rows (`/form/`, `/vennre/khaled-fitforgrowth/`)
already work and are unchanged.

## 2. Ready in code

- **One redirect per old link.** Next.js no longer strips trailing slashes on
  its own (`skipTrailingSlashRedirect`). The app's own sections are normalised in
  `apps/web/next.config.ts`; any other path reaches the legacy route with its
  slash and gets a single redirect to a slash-free page.
- **robots.txt.** Blocks everything on staging and previews. On
  `https://mukhtalif.net` it allows the site, closes account and utility pages and
  names the sitemap (`apps/web/src/app/robots.ts`).
- **sitemap.xml.** Built on request from the live catalogue: static pages,
  programmes, episodes, articles, guests and courses, about 1,300 URLs
  (`apps/web/src/app/sitemap.ts`).
- **Canonical links.** Only the home page claims `/`; course pages name their own
  URL. Before this change, pages without their own canonical inherited the home
  page's.
- **Redirect rows.** `apps/api/supabase/legacy-redirects-cutover.sql`, generated by
  `scripts/legacy-redirects-cutover.mjs` and tested on an in-memory copy of the
  table: 44 new rows, 15 corrected rows, 2 retired rows. Safe to run twice.

## 3. Before cutover

1. **Apply the redirect script** to production (`pacpdxvujkjvnaeeuute`) after the
   team confirms the sponsor destinations. It changes only `url_redirects`. Check
   staging afterwards: the old URLs in section 1 must answer with one redirect.
2. **Sponsor list.** The team lists every sponsor short link in use, with its
   destination and end date. Each becomes a `url_redirects` row (302). A Studio
   screen for managing them is a later piece of work.
3. **Analytics.** The old site loads Google Tag Manager container
   `GTM-5P5FS7CB`. Load the same container on the new site so GA4 continues
   without a gap, and confirm events arrive from staging.
4. **Search Console.** Confirm the `mukhtalif.net` property is verified and who
   has access.
5. **Decide how Hostinger serves the domain** (below), and rehearse it.
6. **Backup.** A full database dump the day before, and a copy of the WordPress
   site that can be restored.
7. **Acceptance pass** on staging: customer sign-up and sign-in, audio and video
   playback, every form and its email, newsletter sign-up, a course purchase path.

## 4. The Hostinger decision

The release workflows deploy a Node.js application to the Hostinger site named
`staging.mukhtalif.net` and refuse any other host. `mukhtalif.net` is a WordPress
(PHP) site today. Two ways to switch:

- **A. Move the domain to the existing Node.js site.** Change the staging site's
  domain to `mukhtalif.net` in hPanel and keep `staging` as a separate review
  site later. Fastest; the running application does not change.
- **B. Create a Node.js site for `mukhtalif.net`.** WordPress is replaced on that
  domain; staging stays as it is. Cleaner separation between review and live, but
  the first deploy to the new site is itself the cutover.

Either way the release code changes in one commit made on cutover day, because a
change merged to `main` deploys immediately:

| Place                                                             | Today                                       | At cutover                                              |
| ----------------------------------------------------------------- | ------------------------------------------- | ------------------------------------------------------- |
| `.github/workflows/deploy-web.yml`, `verify.yml`                  | `PUBLIC_WEB_URL` staging                    | `https://mukhtalif.net`                                 |
| `scripts/deploy-hostinger-web.mjs`, `configure-hostinger-web.mjs` | target `staging.mukhtalif.net`              | the chosen site                                         |
| `scripts/assert-hostinger-web-env.mjs`, `smoke-hostinger-web.mjs` | expect staging and `noindex`                | expect the final host, no `noindex`, robots and sitemap |
| `.github/workflows/deploy-api.yml`                                | `PUBLIC_WEB_URL` staging (newsletter links) | `https://mukhtalif.net`                                 |
| API `CORS_ALLOWED_ORIGINS` (hPanel)                               | studio, staging                             | add `https://mukhtalif.net`                             |
| Supabase Auth site URL and redirect URLs                          | staging                                     | add `https://mukhtalif.net`                             |
| Studio build `VITE_PRODUCTION_WEB_TARGET`                         | `staging`                                   | `live`                                                  |

Building with `PUBLIC_WEB_URL=https://mukhtalif.net` is what removes `noindex`,
opens robots.txt and points canonical links and the sitemap at the final host.

## 5. Cutover day

1. Freeze content changes in WordPress.
2. Merge the cutover commit; watch the API, Studio and Web deploys succeed.
3. Switch the domain in Hostinger (A or B).
4. Check at once: home page, five old article URLs, `/vennre/`, `/petroly/`,
   `/robots.txt`, `/sitemap.xml`, a form, a playback, a sign-in, and that GTM fires.
5. In Search Console, submit `https://mukhtalif.net/sitemap.xml`.
6. For two weeks, check coverage and not-found reports daily; add a redirect row
   for any old URL that shows up.

**Rollback:** reverse the Hostinger switch to WordPress and revert the cutover
commit. Keep WordPress intact until the two weeks pass.

## 6. Open decisions

- **Readable article URLs.** 16 imported articles have placeholder addresses such
  as `/articles/legacy-post-1478` because their WordPress slugs were Arabic. If
  they are to be renamed, it should happen before cutover, so search engines
  learn the final address once.
- **Newsletter, writer and book pages.** They redirect to the closest existing
  page until the new structure adds real pages; then the rows are repointed.
- **Pages left as not found:** `/podform/`, `/authorize/`, `/production/`,
  `/بود/`, `/avnews/` and a test page. Confirm none is still in use.
